Exit Nodes, Two Ways

Mullvad's servers through the Tailscale add-on, or a cloud server you run yourself. Checked against Tailscale's documentation on 8 September 2026.

You have a Tailscale network and you'd like some devices to send their internet traffic out through somewhere else: another country, a fixed address, or just not the café Wi-Fi. The machine that does that is an exit node. Here are the two ways to get one without buying hardware, with the mistakes from an earlier, unattributed write-up fixed.

Option 1

Mullvad add-on

$5 / month

per pack of 5 devices, on your Tailscale bill. 50 countries. Shared address. No server to look after.

Option 2

Your own cloud server

$4 to $6 / month

for a small DigitalOcean droplet. One address that's yours alone, in the data centre you pick. About fifteen minutes of setup by hand. A one-command automation exists but is an untested proof of concept.

How an exit node works

Normally your laptop's web request leaves through whatever network you're on, and the website sees that network's public address. With an exit node selected, Tailscale wraps the request in an encrypted WireGuard tunnel (the fast VPN protocol Tailscale is built on) and sends it to the exit node. The exit node unwraps it, swaps the sender address for its own (that swap is called NAT), and passes it on. The website sees the exit node's address, and the reply comes back through the same tunnel.

Two things follow. The exit node can see where your traffic goes (not what's inside HTTPS), so it should be a machine you trust. And whoever owns the exit node's address is who the internet thinks you are. Tailscale keeps destination logging off for exit-node traffic by default.

Heads-up

By default an exit node also swallows traffic to your local network: the printer, the NAS on the LAN. Every client has an "Allow local network access" switch for that. DNS needs no configuration on clients from version 1.48.3 onward.

Option 1: Mullvad exit nodes

Mullvad is a commercial VPN provider with a good privacy reputation. Tailscale's add-on makes their servers appear in your exit-node list as if they were your own machines, so you don't run Mullvad's app alongside Tailscale (the two used to fight over routing). Tailscale still labels the feature beta.

How it really works

Correction

The usual description, "an isolated Mullvad tailnet peered with yours", isn't how it works. Each of your devices already has a WireGuard key. When you authorise a device, Tailscale registers that key with Mullvad and adds the Mullvad servers to the device's map of the network (their names end in mullvad.ts.net). Your device then tunnels straight to the Mullvad server. Tailscale coordinates; it isn't a hop in the path.

Buying it and authorising devices

  1. Open the admin console: General settings (console.tailscale.com/admin/settings/general).
  2. Scroll to Mullvad VPN and select Configure, then go through the checkout.
  3. Back in Configure, choose Add devices, tick the devices that may use Mullvad, and save.
  4. On each device, pick a location (below). The first time can take up to two minutes to sync.
Correction

The button is Configure, not "Manage" ("Manage add-ons" lives on the Billing page). And it is not "one click": buying the add-on gives no device access until you authorise devices, and each device then chooses its own exit node. The policy-file alternative is a nodeAttrs rule granting the mullvad attribute; you can't mix the two methods, and if the policy over-subscribes your licences they go to devices in the order they connect to the tailnet.

Picking a location, per platform
  • macOS: Tailscale menu → Exit Nodes → Location Based Exit Nodes → Countries.
  • Windows: Tailscale menu → Exit Nodes → Location Based Exit Nodes → Location Based (partial list; the CLI shows all).
  • iOS: Exit Nodes → Location Based. Android: menu → Use exit node, with an Allow LAN access toggle. Apple TV: supported.
  • Command line:
tailscale exit-node list --filter=Sweden
sudo tailscale set --exit-node=se-sto-wg-001.mullvad.ts.net --exit-node-allow-lan-access=true
sudo tailscale set --exit-node=        # back to normal

tailscale exit-node suggest picks a nearby server, and --exit-node=auto:any follows that suggestion automatically.

Privacy, honestly

Correction

Calling this "high anonymity" is misleading, and Tailscale's own docs say so. Tailscale creates and holds the Mullvad account for you, knows which Mullvad accounts belong to which Tailscale users, and can see from its logs which of your devices used which server (turning off client logging on a device removes that). What Tailscale can't do is read the traffic, and Mullvad never learns who you are. Websites see a shared Mullvad address, but you've given up the anonymous, no-account signup Mullvad is famous for. If that's the property you need, buy Mullvad directly.

Correction

"40+ countries" is from the 2023 launch post. Tailscale's docs give no number now and point at Mullvad's list, which currently shows 50 countries, 91 cities and 569 servers.

Option 2: your own cloud server

Same idea, with a machine you rent. It costs about the same as the add-on, gives you an address nobody else uses, and puts the exit wherever your provider has a data centre.

Choosing a box

DigitalOceanThe $4 droplet (512 MB, 500 GB transfer) works; the $6 one (1 GB, 1 TB) suits something whose job is pushing traffic. Per-second billing, so experiments cost cents. Image ubuntu-24-04-x64.
IPv6 is off by defaultTurn it on when you create the droplet, or IPv6 through the exit node won't work. There's no Tailscale one-click image; the setup is a handful of commands.
ElsewhereHetzner includes far more transfer. AWS bills per gigabyte out, which adds up fast for a VPN. Tailscale notes a known issue with Linux VM exit nodes on Google Cloud.
Ubuntu 24.04 LTSStill a good choice and what the commands assume (26.04 exists now; 24.04 stays supported).

Setting it up by hand

  1. Install Tailscale. 
    curl -fsSL https://tailscale.com/install.sh | sh
  2. Let the server forward traffic. A Linux box drops packets that aren't addressed to it; an exit node is a router. 
    echo 'net.ipv4.ip_forward = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
echo 'net.ipv6.conf.all.forwarding = 1' | sudo tee -a /etc/sysctl.d/99-tailscale.conf
sudo sysctl -p /etc/sysctl.d/99-tailscale.conf
    Correction

    This step is often headed "edit sysctl.conf". The commands (which are right) create a drop-in in /etc/sysctl.d/; /etc/sysctl.conf is only the fallback on systems without that directory.

  3. Join the tailnet and offer to be an exit node. Log in through the link it prints. --ssh turns on Tailscale SSH so you can reach the box without managing keys. 
    sudo tailscale up --advertise-exit-node --ssh
    Heads-up, the one that catches everyone

    tailscale up forgets its flags between runs. Run a plain sudo tailscale up later and the server quietly stops being an exit node. Run up once with everything, then make later changes with tailscale set, which only touches what you name:

    sudo tailscale set --advertise-exit-node
sudo tailscale set --auto-update
  4. Leave the firewall alone. ufw and firewalld refuse to forward by default, and that's what Tailscale wants; it adds its own rules. Don't add ufw route allow rules. The one exception: firewalld needs sudo firewall-cmd --permanent --add-masquerade.
  5. The performance tweak Tailscale recommends for exit nodes. Needs Tailscale 1.54+ and kernel 6.2+ (Ubuntu 24.04 has 6.8). It doesn't survive reboots, so the second command makes it run whenever the network comes up. 
    NETDEV=$(ip -o route get 8.8.8.8 | cut -f 5 -d " ")
sudo ethtool -K $NETDEV rx-udp-gro-forwarding on rx-gro-list off
printf '#!/bin/sh\n\nethtool -K %s rx-udp-gro-forwarding on rx-gro-list off \n' "$(ip -o route get 8.8.8.8 | cut -f 5 -d " ")" | sudo tee /etc/networkd-dispatcher/routable.d/50-tailscale
sudo chmod 755 /etc/networkd-dispatcher/routable.d/50-tailscale
  6. Approve it. Admin console → Machines (filter property:exit-node) → the node's menu → Edit route settings → tick Use as exit node → Save. Or let the policy do it for tagged machines: 
    "tagOwners":     {"tag:exit": ["autogroup:admin"]},
"autoApprovers": {"exitNode": ["tag:exit"]},
    Heads-up

    Save the policy before the node registers. A node that joined earlier still needs the manual approval once. And tag the server: tagged devices never have their key expire, so it won't drop off the tailnet in 180 days.

Using it from your devices

Each device chooses on its own; turning it on for the laptop does nothing to the phone.

  • macOS / Windows: Tailscale menu → Exit Nodes → your server. "Allow local network access" is in the same menu.
  • iOS: the control at the top of the app; None turns it off. Android: menu → Use exit node.
  • Command line:
tailscale exit-node list
sudo tailscale set --exit-node=exit-nyc1 --exit-node-allow-lan-access=true
curl -4 https://ifconfig.me          # expect the server's IPv4
sudo tailscale set --exit-node=      # back to normal
Correction

"Very low risk of streaming blocks because the address is dedicated" is backwards. Streaming services and bot detectors block by network range, and cloud providers' ranges are the ones they block. A dedicated address means nobody else is dragging its reputation down; it doesn't make you look like a home connection. Expect the same "mixed" result as with Mullvad, for a different reason.

Automating it

The project this page belongs to turns the server setup into one command against DigitalOcean, as a cloud-init file plus a shell script and as a Terraform module. The automation is a proof of concept validated offline only; it has not yet been run against a live DigitalOcean account. The ideas travel to any provider:

  • Put the policy rules in place first.
  • Use a one-off, pre-approved, tagged auth key with a short expiry. Never an ephemeral one: ephemeral machines are deleted after an hour of silence.
  • Hand the key to the server in a root-only file and shred it after tailscale up. Never on a command line.
  • tailscale up exactly once, at first boot, with every flag. Everything after is tailscale set.
cd automation/scripts
read -rs DIGITALOCEAN_TOKEN && export DIGITALOCEAN_TOKEN   # paste, Enter (not echoed, not in history)
read -rs TS_AUTHKEY && export TS_AUTHKEY                   # paste, Enter
./provision-digitalocean.sh --name exit-nyc1 --region nyc1 --dry-run
./provision-digitalocean.sh --name exit-nyc1 --region nyc1
